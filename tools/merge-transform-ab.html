Node transforms: dropped vs honoured

Sprint S4's visual A/B for the one intentional rendering change in the bump. Every version of the item merge before S4 baked each mesh's local matrix, so a mesh sitting under a transformed glTF node was flattened without its parent's transform. mergeMeshes now uses matrixWorld.

Left is the old reading, right is the new one, and each pair is shown twice because the two questions need different framing. Shared camera is fitted to the union of both results, so a change in size or position shows rather than being normalised away; the grey box is the other side's bounds. Framed individually fits each side to itself, which is the only way to judge whether the corrected model actually looks right — under the shared camera a model that shrank by 100× is a speck.

Watch the second row for distortion specifically. The size figures below are axis-aligned bounds, which cannot tell a rotation apart from a squash: a node that rotates 90° and scales uniformly reports three different per-axis ratios while leaving the model's shape untouched.

Only the affected models are listed, each tagged by what its parent nodes actually do — read off the matrices, not inferred from the bounding boxes, and sorted so the ones that matter come first. Only the strongest effect is shown, since a translation accompanies nearly all of them: moved (24), rotated (2), rescaled (14), stretched (2).

The line that matters runs between the first three and the last. Translation, rotation and uniform scale are all similarity transforms, so every individual mesh keeps its shape exactly and only the two stretched models can have had their geometry deformed. That is not the same as "looks identical": where a model is built from several meshes the fix moves them relative to each other, which is the whole point — bedBunk.glb had a mattress floating off to one side and now has it on the frame.
